# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` holds architecture decisions.

Before exploring, read the glossary and ADRs relevant to the task.
If a document is absent, proceed silently; domain-modeling creates
documents lazily when terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses and tests.
If a needed concept is missing, reconsider the term or flag the gap
for domain-modeling.

Explicitly flag proposals that contradict an existing ADR and explain
why the decision should be revisited.
